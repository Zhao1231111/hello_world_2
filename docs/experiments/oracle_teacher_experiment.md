teacher 应当来自正常的 baseline 联合优化轨迹；回插实验检验的正是：**从这条轨迹中取出一批新 Gaussian 的参数，放到不同于其产生环境的地图状态中，是否仍有初始化价值。** 分工和依赖是这个实验要承受、要观察的条件。

1. **参考轨迹始终正常运行，teacher 只是其中的参数快照。**
  参考轨迹使用规则初始化，新旧 Gaussian 正常共同优化。对插入事件 t，记录这批候选的固定 ID，在后续若干检查点读取这些 ID 对应的参数。
   不额外开一个只优化这批点的过程，不为了生成 teacher 改变参数更新范围。teacher 参数也不写回参考轨迹，插入帧后续依然继续添加高斯，old/new joint optimization。否则之后的标签来源就不再是纯 baseline。
2. **回插只移植这批参数，恢复的是完整的插入前状态。**
  对同一个 insertion 起点建立两个分支：

  | 分支            | 插入前地图    | 本次新增 Gaussian |
  | ------------- | -------- | ------------- |
  | Baseline 参考轨迹 | 原始状态 S_t | 规则初始化         |
  | 回插评估轨迹        | 同一个 S_t  | 从联合优化轨迹提取的参数  |

   teacher 的优化器动量、已经变化的旧地图、相机或曝光参数，都不随新点参数一起移植。新增点的优化器状态按照正常插入规则设置，随后两个分支都正常联合优化。
  teacher参数包含完整的高斯参数。**回归器未来会被重新设计，起输出参数集合包括** scale、rotation、opacity、SH、xyz**，因此这些参数都会作为回插高斯参数。**如果验证效果不好，后续实验还可考虑研究去掉某些参数以获得更稳定的效果。
3. **优化预算应当有一个无歧义的计数。**
  teacher 点的优化预算不应当根据该帧视图被优化了多少次决定，而应该通过这批点被优化了多少次决定。也许我们应该为每一个高斯维护一个优化次数，其判断方式为：本次渲染中该 Gaussian 实际参与了图像合成、对应参数处于可训练状态，并且本次优化更新正常执行，才累计一次。
  当平均次数首次达到或超过目标预算 K，保存这一批 Gaussian 的参数，同时记录实际平均次数。平均值可能不是整数，所以不能要求它恰好等于 K。
  平均的集合始终是原始插入批次，不能临时改成“当前可见的点”。如果有点退出地图，也必须明确记录其状态，避免通过改变分母让预算看起来增加。
  整批参数必须在同一个时刻保存。 不能每个点分别达到 K 时保存，再拼成一批；那样会混合不同联合优化状态，破坏我们想保留和检验的分工关系。
  我们要求视图分配也使用 baseline 原有调度。不在实验中加入此前提到的平均分配。
4. **单次回插先隔离效果，多次回插再测试状态偏移。**
  单次实验从多个 insertion 起点独立分叉，评价附近视图在回插后不同全局优化更新次数下的质量，具体评估方式见下文。整图指标和预先确定的局部区域指标同时保留，避免局部变化被整图平均稀释。
   多次实验则延续我们之前的设置：teacher 始终来自独立 baseline 轨迹；接收 teacher 的轨迹已经包含之前的回插结果。因此，第 j 批参数产生时所面对的旧地图，与实际接收它们的旧地图不同。
   第一轮多次实验重放参考轨迹的候选 ID 和插入事件，以保证移植对象对应。之后再放开各自的候选选择，检查真实闭环表现。这两个实验的结论要分开：前者回答参数对地图状态变化是否稳健，后者回答整个系统是否受益。
5. **回插评估轨迹后续继续接收新帧，其行为除插入外与baseline完全相同**
6. **被prune的高斯不应当作为teacher点插入**
  我预计后续产生数据集时，被prune掉的高斯也被加入数据集，且不透明度被设为低于prune阈值，从而让回归器学习哪些高斯应当被prune。在理想情况下，回归器将会学习出分配规则，在推理时对于需要被prune的高斯回归出很低透明度，从而被系统识别并prune。
  因此对于我们的实验，我们不将那些被prune的高斯插入地图中。
  其中“被 prune”定义为为截至该预算快照时已被删除，不能依据更晚时刻或序列结束时的存活状态决定，否则不同预算会混入额外未来信息。



## 回插后的收敛评估方法

本实验考察 teacher 参数作为初始化后，能否使附近关键帧的渲染质量更快改善。**teacher 快照预算与回插评估横轴分别定义**：预算 K 仍按原始插入批次的平均有效优化次数确定，仅用于选择 teacher 快照；评估横轴使用下面定义的全局更新次数，不使用 K、单个关键帧的训练次数或该批 Gaussian 的平均优化次数。

### 全局更新次数与检查点

定义 G 为系统累计完成的单视图优化更新次数：每选择一个视图完成一次渲染、反向传播及相应参数更新，G 增加一次。一次更新可以同时影响该视图下可见的新旧 Gaussian，并不表示地图中每个 Gaussian 都更新了一次。若一次 `optimize()` 调用依次优化多个视图，应按内部实际更新次数累计，不能将函数调用次数或 `optimize_round_` 作为 G。

对于插入事件 t，记录插入时的全局计数 G_t。**曲线横轴为 s=G**，并标明该事件的 G_t。仅在预定且满足 s>=G_t 的检查点评估

Baseline 对照与回插评估轨迹从同一个插入前状态及全局计数开始，使用相同的全局检查点。检查点频率在运行前确定并记录。每到一个检查点，使用该时刻的同一个地图状态重新渲染所有待检查关键帧，再继续正常优化。评估不增加 G，也不增加任何关键帧或 Gaussian 的优化计数，不改变 baseline 的选帧与更新逻辑。

### 待检查关键帧

待检查关键帧定义为插入帧邻域内的一组关键帧。先采用关键帧序号上的邻域：插入帧及其前后各 m 个关键帧；m 在运行前确定，两个分支使用相同的帧 ID 集合。这里的邻域描述相机视图范围，与图像内部的局部评价区域不同。

检查点处渲染所有待检查关键帧。

### 逐关键帧对比曲线数据

每个待检查关键帧分别记录 PSNR、SSIM、LPIPS，分别绘制其随 s=G 变化的数据。
