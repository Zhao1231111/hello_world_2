### Reviewer 1

**总结（Summary）：**

本文 LIV-Surfel 提出了一种增量式 LiDAR-惯性-视觉 2D Gaussian Splatting 后端。该方法使用补全后的深度、单目法向先验、候选点筛选，以及一个前馈网络，在 surfel 插入时预测其属性。该网络通过自蒸馏进行训练，监督信号来自在线优化后得到的 surfel 属性。论文报告称，与所选择的基线方法相比，该方法改善了新视角渲染指标，并提升了新 surfel 插入后的早期收敛性能。

**优点（Strengths）：**

1. 论文识别出了增量式 Gaussian mapping 中的一个关键问题：新插入的 primitives 在开始影响渲染之前，只能获得有限次数的优化更新。所提出的方法根据当前渲染状态以及历史视觉上下文来预测插入时的属性，从而有效地针对这一问题进行处理。

2. 第 III-C 节中的 surfel 旋转设计是合理的。公式（4）—（5）围绕修正后的法向量构造了一个 surfel 坐标系，这与 2DGS 面向表面的特性相符合，而不是直接预测一个不受约束的四元数。

3. 表 I 给出了在 R3LIVE、MCD 以及自采集数据集上的结果，相比 Gaussian-LIC2 有所提升。图 3 也从视觉上证实了模糊和拖尾伪影的减少。

**缺点（Weakness）：**

1. 尽管论文将系统定位为实时或在线系统，但现有评估并没有证实该系统在实时性或在线运行方面的可行性。第 I 节和第 III 节将该方法描述为一个针对每个关键帧执行的增量式 mapping 后端，而图 1 则展示了一条包含多种处理步骤的完整在线流水线。然而，第 IV-A 节虽然给出了硬件配置，却缺少一些关键数据，包括各模块的运行时间、关键帧处理时间、渲染速度以及内存占用情况。这一点十分重要，因为与更简单的方法相比，DA3 模型以及多视图特征提取可能会带来相当可观的额外计算开销。作者应当提供详细的运行时间分解、关键帧处理速率、地图规模增长统计、峰值内存占用，以及与回归器和外部网络相关的计算开销。

2. 论文声称实现了 geometry-aware mapping，但实验只评估了 PSNR、SSIM 和 LPIPS 等图像渲染指标。论文缺少深度误差、法向误差以及与 LiDAR 几何的比较，而这些对于验证 normal-guided rotation 分支是否真正改善了表面几何是必要的。作者应当加入以 LiDAR 为参考的几何指标，并比较使用和不使用 normal-guided branch 时 surfel 法向的一致性。

3. 当前的消融实验没有将所提出的回归器与系统中的其他变化隔离开来，因此难以验证论文中的一般性结论。表 II 在 hku_campus_00 上比较了 “Baseline” 和 “Ours”，而表 III 展示了早期渲染性能随优化过程的变化，表明确实使用完整的 learned-initialization 配置可以获得提升。然而，这些实验没有区分各个独立组件的贡献，例如历史上下文、cross-attention 等，也没有评估 2DGS 或其他组件对性能的影响。作者应当在多个序列上加入组件级消融实验，例如基于规则的 2DGS 初始化、不使用几何先验的直接属性回归等。

### Reviewer 3

论文提出了 LIV-Surfel，这是一种用于增量式场景重建的前馈系统，依赖几何先验以及 2D Gaussian Splatting surfel 表示。其训练采用自蒸馏方式。实验在自建数据集、R3LIVE 和 MCD 数据集上进行，并显示出一定的性能提升。

**优点（S）：**

* 从深度估计器中引入几何先验是一个有前景的方向，它与单纯通过扩大数据规模来提升性能的路线是正交的。
* 使用法向量来约束 2DGS 表面听起来是合理且顺理成章的一步。
* 这种简单的几何先验设计有潜力较容易地被其他工作采用。
* 对多模态系统进行了直接、清晰的组合。

**缺点（W）：**

**— 系统设计的复杂性**

正如 “A System Overview” 和图 1 所展示的，系统采用了 IMU、Camera 和 LiDAR 的多模态配置。然而，论文同时认为稀疏 LiDAR 不足以提供几何引导，因此使用 SPNet 进行深度补全；即便如此，论文似乎又认为这仍然不是一个足够可靠的信息来源，最终又使用 DA3 作为实际的深度估计器，而 LiDAR 只用于确定尺度。

那么我的问题是：**LiDAR 是否真的有必要？**

由于系统已经搭载 IMU，因此 DA3 的尺度可以通过 IMU 来确定（IMU 提供的加速度和角速度分别具有 m/s² 和 rad/s 的物理单位）。作者是否考虑过对这一情形进行消融实验？这样可以降低该方法对于硬件的要求。

**— 对 DA3 的依赖**

目前所展示出的较优性能，有可能实际上依赖于强大的 DA3，而不是来源于该方法本身的创新。将这两方面区分开来非常重要。

作者是否考虑过其他深度估计器并进行比较？该方法的性能是否能够普遍适用于不同的深度估计器，还是会随着这些估计器性能的不同而产生较大变化，尤其是在能否获得稳定法向方面？

此外，DA3 本身具有 metric depth 的估计能力，另请参见其第 7.4 节以及其中使用的 baselines：

[https://arxiv.org/pdf/2511.10647](https://arxiv.org/pdf/2511.10647)

那么，这是否能够进一步将系统复杂度降低为仅使用相机？

我认为论文如果能够讨论以下方面会更好：

a) 方法对 DA3 的依赖；
b) metric depth estimation 与通过 LiDAR/IMU 传感或校准得到的 metric depth 之间的比较；
c) 如果将当前估计器替换为其他 2–3 个估计器，对几何先验造成的影响——看起来准确的法向估计是这里的关键因素。

多年以来，已有大量文献研究了各种几何先验，包括考虑其不确定性，以及显式或隐式地使用这些先验。例如：

### Reviewer 4

**论文总结（Paper Summary）：**

本文提出了 LIV-Surfel，这是一个旨在改善增量式 3D Gaussian Splatting（GS）mapping 中新 Gaussian 初始化的系统。

论文所解决的核心问题是，传统的基于规则或随机的初始化方式往往会在在线优化过程中导致局部最优、“popping” 伪影以及较慢的收敛速度。

作者提出了一个前馈回归网络，通过利用多模态先验来预测 2D surfel 的初始属性，包括 scale、rotation、opacity 和 SH coefficients。这些多模态先验包括：通过 SPNet 得到的稠密深度补全，以及通过 Depth Anything 3（DA3）得到的法向估计。

为了绕过 Gaussian 属性缺少 ground-truth 标签的问题，作者采用了一种自蒸馏训练策略，将优化之后的地图状态作为训练目标。

在 R3LIVE 和 MCD 数据集上的实验结果表明，与 MonoGS 和 Gaussian-LIC2 等基线相比，LIV-Surfel 能够获得更高的渲染质量（PSNR/SSIM），并且能够显著更快地达到收敛。

**优点（Strengths）：**

* 将重点放在增量式 GS 中的“初始化瓶颈”上具有很高的相关性，并且动机充分，因为这是影响实时 mapping 稳定性的一个已知痛点。
* 在滑动关键帧窗口上使用 cross-attention，可以使模型捕获时序一致性和多视图一致性，这与 SLAM 场景十分契合。
* 自蒸馏循环是一种优雅的回归器训练方式，尤其是在这一领域缺乏明确标签的情况下。
* 定量性能提升以及收敛分析，为该方法能够降低对昂贵迭代优化的依赖提供了有力证据。
* 论文结构组织良好，表述清晰。

**缺点（Weaknesses）：**

* 最主要的问题是 **SPNet 和 Depth Anything 3（DA3）之间存在冗余**。

当前流水线运行了两条独立的稠密估计路径：一条使用 SPNet 进行 metric depth completion，另一条使用 DA3 获得 relative depth / normals。

由于 DA3 已经可以生成高质量的稠密相对深度图，而且作者实际上已经利用稀疏 LiDAR 点对这些输出进行了尺度调整，从而得到 metric dense depth，那么原则上，这一条路径就能够一次性同时提供 metric depth 和 surface normals。

同时运行 SPNet 和 DA3 会额外引入 GPU 显存开销和延迟，但目前并没有清楚解释为什么只使用经过尺度恢复的 foundation model 路径是不够的。

* 作者强调该方法可以减少所需的优化 step 数量，例如可以在 4 steps 而不是 16 steps 后达到某些阈值。

然而，论文没有分析前馈 inference 本身实际需要多少时间。如果在多个关键帧上运行 cross-attention，再加上两个稠密估计模型 SPNet + DA3 的计算成本，超过了减少优化 step 所节省的时间，那么所谓的“效率”提升就只停留在理论层面，而没有实际收益。

* 自蒸馏循环假定优化后的地图是一个可靠的训练目标。

然而，在增量式 SLAM 中，漂移是固有存在的。如果优化器对发生漂移的状态产生过拟合，或者产生了伪影，那么回归器就会将这些错误当作真实目标进行学习。

论文没有讨论如何避免这种 confirmation bias loop（确认偏差循环），也没有说明是否对蒸馏目标使用了任何筛选或正则化措施，以确保只有高质量的 Gaussians 被用于训练。

* 虽然表 3 表明该方法收敛得更快，但目前尚不清楚，在相同的总优化 step 数下，例如 32 或 64 steps，该方法最终是否能够达到比 baseline 更好的局部最优。

如果回归器所做的只是更快地收敛到与 baseline 相同的结果，那么它的价值就纯粹体现在降低延迟方面。

**给作者的问题（Questions for Authors）：**

1. 为什么在使用 DA3 的同时还需要 SPNet？作者能否提供一个消融实验，证明“使用 LiDAR 对 DA3 的相对深度进行尺度恢复”的方案，其性能确实低于使用 SPNet 的方案？

2. 回归器每帧平均 inference time 是多少毫秒？与通过减少 optimization steps 所节省的时间相比如何？如果能够与其他方法的运行时间进行比较，将有助于说明这种质量提升是否“值得”其额外开销。

3. 回归网络的参数量和内存占用是多少？它是否适合部署在 LiDAR-Inertial 系统中常见的嵌入式设备上？与已有方法相比情况如何？
